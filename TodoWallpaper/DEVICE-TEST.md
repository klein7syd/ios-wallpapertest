## Windows 覆盖安装

1. 在阶段 B App 中准备至少三条待办，包含已完成项、自定义顺序和长标题，截图记下内容与顺序。不要卸载 App。
2. 完整解压本 ZIP。iPASide 保持原签名账号已登录，USB 连接并解锁 iPhone。测试期间暂停普通自动刷新，再关闭 iPASide 窗口，避免普通流程删除扩展或覆盖回旧包。
3. 双击 **Install-TodoWallpaper.cmd**。首行应为 Signing repair: 0.2.0-stage-c-r1。脚本复用已安装的 iPASide engine/登录状态，沿用手机上正式 App 的实际 ID，为 App 与 Widget 分别申请 profile 并关联同一共享组。
4. 脚本使用已验证的 R1 修复：先嵌入两份最终 profile，再签名；检查身份、App Groups、全部资源封装与代码哈希，通过后才尝试覆盖安装。不要使用普通拖拽安装来绕过扩展检查，也不要删除扩展。
5. 签名工具成功、设备安装服务成功、真机功能通过是三个不同结果。遇到错误保留现有 App，发送控制台报错，不要卸载或改账号。

iPASide 可能已将团队后缀附在正式 App ID 后。脚本读取并保留现有 ID，扩展实际 ID 为该 ID + .widget；共享组为源码组 ID + 同一团队后缀。后续继续使用同一账号、映射和本脚本。签名资料只在 Windows 本机，不上传 GitHub。

## 真机验收（按顺序）

- [ ] 覆盖后仍是原 Todo Wallpaper 图标；关于页版本为 0.2.0、新构建号，实际安装标识沿用旧值。
- [ ] 第一次打开后，原待办的数量、文字、顺序、完成状态完整保留。关于页显示“共享存储已就绪”。
- [ ] 添加系统小号、中号、大号 Todo Wallpaper 组件，核对未完成任务顺序、完成计数、长文字和“另有 N 项”提示。
- [ ] 划掉主 App，在主屏幕直接点击未完成任务的圆圈；状态更新，且不跳入主 App。
- [ ] 打开主 App，核对刚才的任务已完成。回组件点击已完成行，可直接恢复，再核对 App。
- [ ] 在主 App 新增、编辑、删除、拖动排序及完成任务，回主屏幕核对组件。记录实际刷新延迟；需要时用“关于 → 请求刷新小组件”。
- [ ] 没有待办时显示空状态；全部完成时显示完成状态并允许恢复一条近期完成项。小尺寸无法列出全部任务，会显示剩余数量。
- [ ] 重启 iPhone，再核对任务、顺序与状态。
- [ ] 再次运行本脚本覆盖同一版本，所有数据保留，没有重复导入旧待办。后续更高构建覆盖仍需随下一版实测。
- [ ] 原生底部导航、增删改和深浅色仍然正常。

Widget 只在系统提供的空间内展示，长标题按尺寸分行/省略；不提供滚动列表。任务行按钮执行 App Intent，不使用跳转冒充操作。点空白处打开 App 是系统的常规行为。刷新由 iOS 调度，不承诺后台每秒刷新。

## 数据迁移与恢复

旧位置：私有 Application Support/TodoWallpaper/todos-v1.json。新位置：App Group 容器内 TodoWallpaper/todos-v1.json。文件 schema、任务 UUID 和排序不变。

主 App 首次打开时执行迁移，逐字节验证复制并检查文档结构后才发布就绪标记。原私有主文件与备份不删除，另保留迁移快照。Widget 在标记就绪前不会创建空文件或写入数据。

共享数据已存在或迁移已确认后，不再把旧版副本导入，不会覆盖较新数据。权限缺失、组标识不一致或共享主文件丢失时会报错，保留原数据。App 和 Widget 不会各自退回私有存储。

若出现读取/迁移错误，先截图并点“重新读取”。签名权限问题需沿用原账号重新签名后重试。真正的数据文件损坏且有有效备份时，会提供“从上次备份恢复”，确认后先另存损坏文件再恢复；备份可能少一次修改。未来版本数据不会被旧备份自动回退。不要通过卸载排错。
