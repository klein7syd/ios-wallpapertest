# PRODUCT — 产品意图

来源：用户 2026-10-27 分享的早期交接对话（`chatgpt.com/share/6ae08b45…`）。
这份文件回答的是「为什么做这个 App」，代码和文档回答不了。

## 一句话

把待办放进用户每天都会看到的壁纸和主屏幕小组件里，让用户**不打开 App** 也能看见、也能打勾。

## 用户是谁

- 一台 Windows 电脑 + 一台 iPhone 13 Pro，**没有 Mac**，不打算买 99 美元的开发者账号。
- 主屏幕空间宝贵，讨厌为了勾一个待办专门去开一个 App。
- 自己在用这个 App：每做完一个能跑的版本就装到真机试，试完给反馈。

## 三条不可动摇的判断

1. **壁纸负责展示，小组件负责操作。** 导出的壁纸是静态图片，上面的圈不能点，也不会随 App 自动变。这是限制，必须说清楚，不能包装成功能。
2. **少打开 App、少占主屏幕。** 任何让用户多戳一次的设计都值得被质疑。
3. **不虚构能力。** 没有真正实现的通知、换壁纸、AI，不许在文案或文档里写成已实现。

## 明确不做

- 不做 PWA / 网页版作为最终形态（2026-10-24 已叫停，PWA 只做过过渡验证）。
- 不做 WebView 套壳。
- 不做云同步、账号体系。
- 当前阶段不接 AI。将来若接，必须把「虚构内容」和「真实语录」标清楚。
- 当前阶段不做订阅。

## 界面约束（用户明确指定，别自作主张改）

保留：四个底栏入口、连续流体胶囊、非模态质感 HUD、中性玻璃、左侧图标。

不恢复：模拟大时钟、右侧优先级圆点、独立的「加面板」Tab。

## 路线图（2026-10-24 制定）

| 版本 | 内容 |
|---|---|
| v0.1 | 原生能启动，待办增删改查 + 本地保存 |
| v0.2 | WidgetKit + App Groups + App Intents，组件上直接完成 |
| v0.3 | 高清壁纸 / 预览 / 缓存 |
| v0.4 | 快捷指令可行性验证 |
| v0.5 | 文本导入 / 韩中内容 |
| v0.6 | AI 接入 |

当前 0.5.1 大致落在 v0.3–v0.4 之间，但跳过了 v0.4 的快捷指令闭环。

## 验收规矩（用户定的，优先于任何进度压力）

- 每个版本做完就**停**，等真机反馈再继续。
- 编译通过 ≠ 真机通过。
- 没有实际构建、签名、设备测试，不许说安装成功。
- 不许把 HTML 预览通过当成 iOS 真机测试通过。
